# Integration Sweep — 2026-04-11

First cross-slice sweep for cairn. Runs after SLICE-001 (`validator-symlink-fix`)
reached status `complete`. `sweep-interval: 1`, so the sweep triggers every slice.

## Scope and context

Cairn is a methodology repo, not a runtime application — there is no
long-running process, no database, no MCP surface, no module graph beyond
`scripts/validate_architecture.py` and the three shell hooks. Most of the
"cross-slice failure modes" the generic `/integration-sweep` enumerates
(schema drift, tool-contract breaks, config conflicts, module boundary
violations) are inapplicable by construction. The failure modes that *do*
apply for cairn are:

1. **INV-001 violations** — direct commits that bypassed `/start-slice` or
   `/decision` without a superseding ADR.
2. **ARCHITECTURE.md ↔ ADR drift** — an invariant that cites a non-existent
   or superseded ADR, or a firm ADR with no paired invariant. (The
   substrate validator `scripts/validate_architecture.py` checks this.)
3. **Canonical-path drift** — hooks or scripts that edit via the
   `.slice-system/` prefix instead of canonical paths (CLAUDE.md §"always
   edit canonical paths").
4. **Self-symlink recursion hazard** — any new tool that walks the repo
   root recursively and loops on `.slice-system → .`.
5. **Hook dependency regression** — a hook whose graceful-fallback path
   (missing `jq` / `ruff`) silently disables enforcement.
6. **Slash-command path reference drift** — commands in
   `commands/claude-code/` that reference files which have been moved,
   renamed, or deleted.
7. **Scope-guard canonicalization hazard** — the `.slice-system/foo.sh`
   path-stripping bug documented in CLAUDE.md.
8. **Latent test/lint regressions** — the repo-wide ruff + pytest + syntax
   checks did not run on any commit prior to this sweep.

**Status: FAIL.** Exactly one post-bootstrap commit (`f531087`) was not
routed through `/start-slice` or `/decision` and is not recorded in a
superseding ADR.

**What `f531087` changed**: a 3-line addition to `CHANGELOG.md` under
a new "Known issues" subheading, documenting the
`scripts/validate_architecture.py:22` symlink-resolution bug that SLICE-001
subsequently fixed. No code change. The commit message is self-consistent:
it identifies the bug, cites the line, and scopes the fix to cairn.

**Why it happened (inferred, not excused)**: the bug was discovered during
a consuming-project session (see the untracked
`docs/2026-04-11-review-from-rag-session.md`, Finding 1). The author
recorded the symptom in `CHANGELOG.md` before opening the fix slice.
Pragmatically: a "known issue needs to be written down somewhere" impulse
running ahead of the pipeline. INV-001 does not make this allowance.

**Why SLICE-001's own Phase 4 did not catch it**: SLICE-001's
integration/sweep-notes.md (line 62–64) explicitly notes: "The sole
invariant in cairn's architecture (INV-001 …) is unrelated to validator
resolution and is not affected by this slice's changes." Phase 4 checked
that *this slice* did not violate INV-001, not that the repo-as-a-whole
satisfies it. That gap is exactly what a cross-slice sweep is for.

**Remedy options** (user decides — sweep does not retroactively edit
history):

1. **ADR-002 to expand the bootstrap window.** Write a new ADR —
   `firmness: firm`, `supersedes-sections: []` against ADR-001 — that
   clarifies the scope of "the bootstrap" as covering all setup work
   between `25ff49f` and the first `phase 1 intent` commit of SLICE-001,
   retroactively regularizing `f531087`. This preserves INV-001's
   forward-going teeth without rewriting history. Closest fit to the
   spirit of ADR-001's own "no second exception" clause, because it
   *names* the scope rather than creating a second exception.

2. **ADR-002 to narrow INV-001.** Scope INV-001 to commits that touch
   substrate code (`checks/`, `scripts/`, `commands/claude-code/`),
   excluding `CHANGELOG.md` and `docs/` entries that record state rather
   than change behavior. Weakens the invariant; not recommended — a
   footnote commit to CHANGELOG is still development work.

3. **Accept the violation as a scar.** Record it in `docs/lessons.md` as
   "pipeline-bypass temptation: the urge to 'just write down the known
   issue' before opening a slice." Leave INV-001 unchanged. Accepts that
   the repo has one un-remediated violation in its history, and that the
   first cross-slice sweep found it. Honest, costly, educational.

Recommendation (sweep's view, not a decision): **option 1**. It honors
ADR-001's "no second exception" language because ADR-002 would be a
supersession of *a section* of ADR-001, not a second independent
exception. The operational effect is a narrowly-bounded, historically
anchored amendment.

**Whichever option is chosen, this sweep report itself should not drive
the fix.** If the user agrees with option 1, a `/decision` session (or a
direct `/new-adr` if the scope is small enough) creates ADR-002 through
the proper channel. The sweep's job is to surface the issue; the decision
protocol's job is to resolve it.

## Adversarial questions I asked myself while sweeping

A cross-slice sweep is structurally adversarial — I enumerated the
following questions in order to try to break the current state, not
confirm it.

- *Does the new `CLAUDE_PROJECT_DIR` resolution path in
  `validate_architecture.py` create a surface where a consumer can
  accidentally validate cairn's own docs?* No. V5
  (`test_v5_consumer_with_broken_substrate`) and V6
  (`test_v6_resolution_failure_no_viable_root`) specifically assert that
  a broken-substrate or unresolvable-root case must not silently read
  cairn's substrate. V6 uses the literal-substring assertion `"Invariants
  verified: 1" not in result.stdout`, which is load-bearing because cairn
  has exactly 1 invariant.

- *Does SLICE-001's envelope creation of `.claude/current-slice/integration/`
  break any assumption about directory shape elsewhere?* No. The
  scope-guard default allowlist covers `.claude/current-slice/*`.
  `integration/sweep-notes.md` is a Phase 4 artifact, unrelated to
  cross-slice sweep output (which lands under `.claude/sweep-results/`).

- *Is there any file that the validator's resolution changes would
  cause to be re-read by a different code path — e.g., a slash command
  or hook that assumes the old `Path(__file__).resolve().parent.parent`
  mechanism?* No — the hooks do not call the validator, and the three
  slash-command callsites invoke it as a subprocess with no path-probing
  before the call. The behavior change is invisible to existing callers
  on the success path.

- *Is the `ALL CHECKS PASSED` stdout marker stable enough to be relied
  on by any external tool?* `commands/claude-code/status.md:42` reports
  pass/fail based on the validator's exit code, not stdout parsing. No
  external tool greps for the stdout marker. Stable.

- *Does this sweep itself, by writing
  `.claude/sweep-results/2026-04-11-sweep.md` and potentially committing
  it, create a recursive INV-001 violation?* Open question. See
  §Recursive tension below.

## Recursive tension (worth naming)

This sweep is about to create a commit (per step 6.5 of
`/integration-sweep`) that is not a slice commit and not a decision
commit. INV-001's letter forbids that. INV-001's spirit — "every unit of
cairn development flows through the pipeline" — arguably allows it,
because `/integration-sweep` is itself part of the pipeline substrate
(same category as `/start-slice` and `/decision`).

The sweep protocol explicitly says to commit the results. The user's
invocation of `/integration-sweep` is a durable instruction that authorizes
following that protocol. So this commit is *authorized*, but it is not
*routed through* `/start-slice` or `/decision`.

This tension mirrors the `f531087` question and is probably worth
resolving as part of whichever option the user chooses above. A clean
fix would be: ADR-002 (whatever form) should say that `/integration-sweep`
and `/refresh-architecture` commits are part of the pipeline and are
covered by INV-001's spirit, same as `/start-slice` phase commits. Until
then, this sweep commit is also technically a violation, by the same
strict reading.

I mention this not as a dodge but because finding-it-and-then-committing-
while-committing-another-of-the-same-kind would be exactly the kind of
quiet drift the sweep is supposed to prevent.
