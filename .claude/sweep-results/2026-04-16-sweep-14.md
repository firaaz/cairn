**Failure:** `AssertionError: assert 6 == 4` — test hard-codes 4 lines; post-merge `.claude/d3-bypasses.log` has 6 (4 pre-existing SLICE-012/014/016/017 + 2 from the SLICE-018 batch: A's envelope-expansion entry and C's scope-deviation entry).
**Worker that wrote the test:** B (`slice/v1-defense-d3-log-reclass`). Test was written during B's Phase 2; B could not anticipate that A and C would each append their own SLICE-018 lines during merge.
**Scope note:** Per skill rule 9, this sweep does NOT retroactively patch B's test. The fix is a follow-up slice that either:
- Replaces the count assertion with a format-per-line assertion (each line matches the classified schema), OR
- Parameterizes the count (assert ≥ `N_LEGACY` + expected current-slice entries).
**Category:** This is a **real ADR-007 parallelism cost**: the "sister-branch edits the same file" class of test brittleness. Previously theoretical (ADR-007 Risk Register #2); now an observed-and-measured cost.
