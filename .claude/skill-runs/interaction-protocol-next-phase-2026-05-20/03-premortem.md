# Phase 1 — Adversarial Pre-Mortem

## Per-branch failure scenarios

### Branch RETROFIT

1. **Edit-anchor exhaustion on minority-shape ADRs.** Trial B established the `old_string` must start with `firmness:`/`status:`/`superseded-by:`/`superseded_by:` rule (verified `checks/reversibility-guard.sh:85`). For ADRs whose frontmatter already places `name:` insertion adjacent to `id:` (the natural spot), the Edit must instead anchor at `status:` or `firmness:` further down and inject `name:` upward. For ADRs like `semantic-identity.md` (which has both `title:` AND `status:`), the implementer must decide: rename `title:` → `name:`, leave `title:`, or add both. Each of 14 ADRs is a micro-decision the journey-trace treats as mechanical. Post-failure evidence: 14 inconsistent edit shapes; some ADRs end up with `name:` + `title:` duplication, others single-field, others reordered. Not addressed by Phase 0/0.5 — 02-journey.md:22 names the new-key gate concern but waves it off as "test one edit locally."

2. **`name:` text authorship is an LLM-rubber-stamp pit.** 14 ADRs need human-quality `name:` strings. A subagent or sloppy operator producing `name: "Bootstrap exception"` (lowercased restatement of `id:`) adds no human value, defeats the D1 purpose, and silently lowers `LEGACY_LABEL_BASELINE` while leaving the artifact still semantically unlabelled. Post-failure: `git diff` shows 14 `name:` additions; six months later the operator can't tell ADRs apart in the index. Trigger: RETROFIT framed as "mechanical" lowers care threshold. Not addressed by 0.5 — exit criterion ("name is human-sensible") is one spot-check, not 14.

3. **Baseline-decrement race + advisory rot.** Test enforces `unlabelled ≤ LEGACY_LABEL_BASELINE`. If RETROFIT fixes 14 ADRs but the operator forgets to lower the constant in `tests/unit/test_identifier_scheme_contract.py` to 0 (or the new floor), the test stays GREEN forever at baseline=10 — the contract becomes inert. Symmetric failure: lower it too aggressively (= 0) and any *new* ADR landing without `name:` between RETROFIT and the next commit fails CI for an unrelated author. Trigger: D7 migration is "forward-only" per Trial B spec; the baseline-lowering is operator discipline, not a hook. Evidence post-failure: months pass, baseline still at 10, drift creeps back.

4. **Slice-id violation forces a hidden D3 decision.** 6 slice ids violate D2; per 01-constraints.md the resolution is "advisory baseline" (no rename). But `substrate/orchestrator-paths` (from `orchestrator-paths.yaml`) violates the prefix-matches-parent rule — a *prefix-shape* violation, not just casing. Treating it as advisory normalises a structurally wrong id. RETROFIT framing says "accept legacy" but doing so for prefix-mismatch quietly establishes precedent that hierarchical slice ids needn't match parent. Post-failure: a future feature schema audit finds the test enforces nothing meaningful on hierarchical structure.

### Branch TRIAL-C

1. **Phase 1 → Phase 2 dispatch has no pause; intent-contract review gate must amend the skill itself.** Verified `commands/.../SKILL.md` lines 60–67: Step 4 dispatches P1 → Step 5 verifies commit → Step 6 dispatches P2 with zero operator interaction. The `phase-1-tdd.md` agent literally states "Operator review of the committed intent.md before Phase 2 dispatch is the existing flow; that's review, not a structural gate." Memory note `feedback_intent_is_the_contract` flags this is a *known* gap. TRIAL-C as designed in 0.5 (state-transition step 4: "skill loops back to operator with intent + contract") requires an SKILL.md amendment, agent prompt edits, AND a UX decision about how the skill pauses. That's protocol-pipeline-shape work, not a "trial." Post-failure: the trial conflates "shape a contract for intent" with "add the first synchronous operator gate to cairn-tdd-feature" — same conflation that broke Trial B's must-not-violate. Phase 0.5 mentions this gap (line 103) but lists it as "Verify" not "scope-bearing."

2. **Semantic-drift validators are categorically different from filesystem checks.** Trial B's six tests are filesystem scans: presence of keys, regex on id shape, set-resolution for cross-refs. All deterministic, fast, false-positive-free. The example TRIAL-C `must-satisfy` clauses in 02-journey.md:67 ("Specification names the observable behavior, not the implementation"; "Risk Surface names domain-level failure mode, not generic risk") require *judgement*, not parsing. Mechanism options: (a) regex blacklist of "generic" phrasings (high false-positive); (b) LLM judge (introduces non-determinism into the validator layer cairn explicitly built around git-log-walk + structural-parser per `invariant-binding-strategy`); (c) human-checklist (= the existing prose review, dressed in YAML). Post-failure: the test file either becomes a fragile regex zoo or starts shelling out to an LLM — both contradict `invariant-binding-strategy/D1`. Phase 0.5 admits semantic-drift difficulty (line 59) but doesn't enumerate which validator type would even apply.

3. **Phase 2 cannot consume a contract it didn't author — TDD isolation breaks.** The SKILL doctrine (SKILL.md line 13): "Phase 1 cannot see Phase 2's tests; Phase 2 cannot see Phase 3's impl." TRIAL-C wants Phase 2's tests to *cite contract clauses authored by Phase 1*. This either (a) leaks Phase 2 design into Phase 1's contract (Phase 1 effectively writes the test plan), defeating phase isolation, or (b) leaves Phase 2 to interpret abstract clauses with its own bias — the rubber-stamp surface Trial C aimed to defeat. Post-failure: Phase 2 outputs reveal it re-derived clauses Phase 1 already wrote, plus a clause Phase 1 didn't write; coverage map (P4) flags untestable clauses. Trigger: 02-journey.md:54 presents this as "skill brief includes the contract block as structured input" — but doesn't engage with the isolation tradeoff.

4. **Contract amendment authority for non-ADR artifacts is undefined.** ADRs are append-only with documented escape hatches (`reversibility-guard.sh` + `ADR_EDITORIAL_FIX`). Intent.md is a skill-run artifact under `.claude/skill-runs/<feature>/`, which `role_guard.py` ROLE_POLICIES limits to phase-1-tdd, then locks. If Phase 2 finds the contract ambiguous, who edits intent.md? The skill provides no re-dispatch contract; `triager-tdd` re-dispatches the *same* phase. Post-failure: trial blocks waiting for an authority chain that doesn't exist; operator hand-edits, breaking phase isolation. Phase 0.5 names this (line 105) and recommends "explicit policy" — but TRIAL-C is supposed to *use* the policy, not write it.

### Branch TIGHTEN-FIRST

1. **Tightening without a second instance over-fits to Trial B.** Schema-amendment-threshold says N≥3 to widen via supersession. TIGHTEN-FIRST proposes to *narrow* the contract shape based on N=1 instance of "too strict" verdict (Trial B's plan-level execution-scope clause, not the contract-block-shape itself). The 0.5 plan (line 115) lists candidate tightenings (versioning, escalation field, audience tag) drawn from intuition, not from a second contract instance hitting the wall. Post-failure: TIGHTEN-FIRST lands `contract-and-protocol-v2.md` exploratory, then TRIAL-C surfaces *different* problems requiring v3. The tightening was solving the previous war. Trigger: confusing the `feature-schema-d5-reconciliation` plan-contract failure with an identifier-scheme contract-block-shape failure (the relevant ADR is `adr-contract-execution-scope-clause.md`, not identifier-scheme).

2. **TIGHTEN-FIRST creates an ADR that supersedes its own justification.** 02-journey.md:115 specifies `contract-and-protocol-v2.md` "supersedes or supplements identifier-scheme D1–D9 with refined contract-block shape." But the identifier-scheme ADR's contract block is firm, INV-005-bound, and was Trial B's *output*. Superseding it requires N≥3 per `schema-amendment-threshold`. The branch begins with a constraint violation. Workaround per 02-journey: file as `exploratory`. Post-failure: an exploratory ADR refining a firm one is a status-mismatch precedent — either the exploratory binds nothing (so why exist?) or it binds the firm one (so it's not exploratory). Trigger: branch design imports ADR semantics it then has to bend.

3. **Backward-compat with two contracts in flight is ungoverned.** Trial A handoff-contract and Trial B identifier-scheme-contract both exist *and are firm-bound*. If TIGHTEN-FIRST introduces `contract-version: 1|2`, the test fixtures must accept both. `test_identifier_scheme_contract.py` currently parses one shape; v2 + v1 coexistence means dispatch-on-version logic in the test layer or a re-run on the v1 shape. Either way, two test paths to maintain. Post-failure: v1 quietly rots (no one updates the fixture); v2 becomes the new strict, but the test for v1 stops failing on drift because no one writes the dispatch. Trigger: 02-journey:150 names this as "policy missing" — but TIGHTEN-FIRST is supposed to *be* the governance step.

## Load-bearing claim audit

1. **Claim:** Trial B's "too strict" verdict signals structural artifact-scope/execution-scope conflation in the contract pattern itself.
   - **Status:** CONTESTED.
   - **Attack:** Counter-evidence is the existence of `docs/adr/adr-contract-execution-scope-clause.md` (visible in `ls`) — Trial B's verdict already produced a *targeted* ADR amendment. The fix is local, not structural. The verdict commit `a0e3fe6` titled "operator verdict — works, but might be too strict" reads as a calibration note, not a refutation. Plan-level contract (not the ADR contract block) was where execution-scope conflation occurred — those are *different surfaces*. Treating one plan-doc clause failure as evidence of contract-pattern brittleness is over-generalisation from N=1.

2. **Claim:** Slice-intent semantic drift detection is qualitatively harder than Trial B's file-state checks.
   - **Status:** VERIFIED (read `tests/unit/test_identifier_scheme_contract.py:50–80`).
   - **Attack:** Trial B's six tests are pure filesystem scans (presence, regex, set membership). Verified by reading the test file: each assertion is one yaml.safe_load + a key check. No semantic judgement is encoded. By contrast, the example intent must-satisfy clauses in 02-journey.md:67 ("Specification names the observable behavior") require linguistic judgement. The shift is from `O(parse)` to `O(NLP)`. Counter-attack on the claim itself: the qualitative gap doesn't mean TRIAL-C is *infeasible*; it means TRIAL-C is a different category of validator (LLM judge or human checklist), not a stretching of the pattern. The claim under-states the gap — it's not "harder," it's a different validator class.

3. **Claim:** TRIAL-C requires an operator review gate before Phase 2 dispatch that does not currently exist in cairn-tdd-feature.
   - **Status:** VERIFIED.
   - **Attack:** Read `.claude/skills/cairn-tdd-feature/SKILL.md` Steps 4–6 and `.claude/agents/phase-1-tdd.md`. SKILL.md goes from Phase 1 dispatch directly to Phase 2 dispatch with only a commit-verification step between. phase-1-tdd.md explicitly states the operator review is "the existing flow; that's review, not a structural gate." Memory note `feedback_intent_is_the_contract` corroborates this is a known gap. The claim is correct. Sub-attack: the existence of an *informal* review convention complicates "does not exist" — the gate exists socially, not mechanically. TRIAL-C must convert convention to mechanism, which is a SKILL.md amendment, not a contract-design task.

4. **Claim:** RETROFIT is zero-decision, low-risk mechanical cleanup.
   - **Status:** CONTESTED.
   - **Attack:** Verified by sampling three ADRs (`bootstrap-exception.md`, `feature-slice-model.md`, `semantic-identity.md`). RETROFIT carries at least four implicit decisions: (a) when `title:` exists, do we rename to `name:`, add `name:` alongside, or leave `title:` in place; (b) for each of 14 ADRs, who/how authors a human-quality `name:` string (subagent? operator? quality bar?); (c) whether `LEGACY_LABEL_BASELINE` drops to 0 atomically or per-ADR; (d) the 6 slice-id violations include `substrate/orchestrator-paths` — a prefix-mismatch — which the "advisory" framing accepts but which silently legitimises hierarchical-id drift. None of these are mechanical. RETROFIT is "no new ADR" but "many small editorial decisions" — the latter is precisely the surface where rubber-stamping bites.

5. **Claim:** The Phase 0.5 recommended sequence (RETROFIT → TIGHTEN-FIRST → TRIAL-C) limits rework and is the correct ordering.
   - **Status:** CONTESTED (and 02-journey.md was told not to recommend a sequence).
   - **Attack — opposite ordering (TRIAL-C first as forcing function):** TIGHTEN-FIRST without a second contract instance is solution-without-problem; TRIAL-C surfaces the *actual* shape-stresses (semantic-drift detection, audience-mismatch). Doing TIGHTEN-FIRST first means tightening blind. TRIAL-C-first risks rework but produces ground truth.
   - **Attack — parallel:** RETROFIT is independent (operational cleanup of 14 ADRs). TIGHTEN-FIRST and TRIAL-C share design surface (contract shape) — they're not parallel-safe. Parallelism is RETROFIT alongside one of the other two.
   - **Attack — only one branch:** RETROFIT alone is decision-deferral (the operator goal was "do C"); TIGHTEN-FIRST alone yields an exploratory ADR with no second instance to validate against; TRIAL-C alone produces the maximal learning per session. Dropping the others is defensible if shipping the dispatch skill broadly is the real constraint.
   - **Meta-attack:** The "ascending decision-weight" framing presumes the operator's bottleneck is decision-risk-tolerance. If the bottleneck is calendar-time-to-validate-the-protocol, descending order (high-risk-first) dominates.

6. **Claim (new, from 01-constraints.md):** Contract-shape brittleness is a cross-branch risk inherited by RETROFIT/TRIAL-C unless TIGHTEN-FIRST runs first.
   - **Status:** CONTESTED.
   - **Attack:** Brittleness was diagnosed from one plan-level contract incident, in a /decision arc, not in the ADR contract block. RETROFIT doesn't write new contracts — it applies existing firm clauses. TRIAL-C writes a new instance, but the shape-stress it exposes (semantic-drift validator class) is *not* the stress TIGHTEN-FIRST was designed to relieve (audience tagging, versioning, must-satisfy-optional). The "inheritance" framing assumes a single failure axis; there are at least two.

7. **Claim (new):** "Trial B caught its own rule violation and chose to bend" framing implies a structural shape defect.
   - **Status:** CONTESTED.
   - **Attack:** Reading the Trial-B plan (lines 100–180) shows the bend was on the *plan-level enabling-work clause*, not the ADR contract block. The ADR contract block itself was unaffected. The lesson L-024 captures this as a plan-doc-shape lesson, not a contract-block-shape lesson. Conflating the two inflates TIGHTEN-FIRST's apparent value.

## Cross-branch failure modes

1. **Operator-bandwidth-shape mismatch.** All three branches presume operator bandwidth for another mid-weight contract-iteration cycle. The actual constraint may be "ship the dispatch skill (cairn-tdd-feature) broadly so external consumers exercise it." If so, all three branches are local-optimisation against the wrong constraint. Evidence: M5/M7 plugin work in `docs/adr/m5-*` and `docs/adr/plugin-payload-transport.md` are queued but uninvoked here. The /decision frame is "next phase of the interaction-protocol reframe" — but the operator may prefer "next phase = distribute what's stable." All three branches assume more cairn-internal work; none consider "freeze + distribute."

2. **Trial A/Trial B contract stability assumed.** All three branches treat Trial A (handoff) and Trial B (identifier-scheme) as load-bearing fixed points. But the `feature-schema-d5-reconciliation` /decision arc landed `schema-amendment-threshold` and `adr-contract-execution-scope-clause` ADRs *between* Trial B's commit and now. If those ADRs implicitly re-shape what a "firm" contract means (e.g., the execution-scope clause materially changes how `must-not-violate` is read), then the "stable base" assumption is wrong. RETROFIT applies a possibly-already-shifted contract; TIGHTEN-FIRST tightens against a moving target; TRIAL-C extends an already-amended pattern.

3. **All three branches treat the slice-id D3 immutability tension as deferrable.** 01-constraints.md notes 6 slice-id violations accepted as advisory ceiling. RETROFIT codifies the deferral. TRIAL-C and TIGHTEN-FIRST inherit. But the longer the advisory baseline sits, the more new features risk introducing more violations (the baseline only catches *worsening*, not *staying stuck*). Cross-branch: none of the three resolves whether D3 immutability is real or aspirational. The next /decision is forced to revisit it; today's choice silently votes for "aspirational."
