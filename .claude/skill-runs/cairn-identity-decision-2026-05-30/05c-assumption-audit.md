## Verdict (the two hinges)

**A1 — does C3 survive the pipeline?** **No, not as a clean property, and the mitigation is not a mechanism.** C3 is rock-solid **per single dispatch** (VERIFIED, `landscape.md:98`) — but arc A's *own* landscape says isolation "does NOT [hold] automatically across a multi-PHASE pipeline orchestrated from one parent… degrades on the RETURN channel when the orchestrator accumulates each phase's return" (`landscape.md:120`). The charter cycle puts one lead orchestrating harvest→(decision)→build→verify; the workers stay clean, the **lead** accumulates every capped return + formation chat + (worst case) a full in-window /decision sub-arc. The "inter-step channel = committed git artifact" mitigation **is real today but is SKILL.md prose** (`SKILL.md:64,68,72,76` parse only status+commit_hash, rebuild briefs from `git show`) + the agents' honor-system `<=100w` cap (`phase-*-tdd.md:29/25/26`) — enforced by **no hook** (`settings.json:24,44`), and living in the exact SKILL.md the charter cycle rewrites. So A1 = **VERIFIED per-dispatch / ASSUMED-and-false across the pipeline / mitigation is disciplined-prose-not-mechanism.** A's foundational verdict survives only if the ADR hardens proviso (a) into an enforced return-contract.

**A2 — is cross-model verify real or aspirational?** **Buildable, but currently aspirational on the charter path, and unenforced.** The native primitive is real (per-subagent `model:`, `landscape.md:20,86`) — VERIFIED. But: (i) **no phase agent carries a `model:` field** (`phase-{2,3,4}-tdd.md:4`); per-phase model exists only as the **legacy-orchestrator `AGENT_MODEL_CONFIG` dict** spliced via `--model` CLI args (`cost-discipline.yaml:13,17`), a path the SKILL.md dispatch doesn't use — so it's net-new build for the charter cycle, not inherited; and (ii) **nothing enforces** a different family for verify (`landscape.md:108,134` "neither cairn nor any native runtime ENFORCES cross-model review"; brainstorm-1's one mandatory invariant is silent on model). In-repo precedent **L-012** (`docs/lessons.md:225,231`) shows an unenforced, tier-sensitive hook silently failing until a tier flip. **If cross-model verify stays optional — like the dead re-injection hook and dead `AGENT_ROLE` — A's distinctive S3 edge over B evaporates** and build≠check reverts to role-purity (~60% shared blind spots), which B already has. A2 = **VERIFIED-buildable / ASSUMED-enforced.**

## Single weakest load-bearing assumption the whole decision rests on

**That "input-reactive over-steering" is a real, recurring cairn failure mode worth canonizing a co-equal identity around — ASSUMED, pure operator self-report, zero in-repo evidence.** Every *mechanism* the charter cycle adds (amendment log, surface-don't-switch, re-injection hook) presupposes this failure exists and bites in cairn. Yet no cairn artifact logs a reactivity/whipsaw incident (grep of `docs/` finds only unrelated "reactive" uses); by contrast the cliff/drift failures the substrate fights have logged incidents (L-012/L-016/L-022). This is weaker than A1/A2 because those are at least *partly* verified (per-dispatch C3; native model primitive) and *fixable in the ADR* (harden the channel; commit cross-model verify). The motivating-failure assumption is **neither verified nor fixable by any build deliverable** — the proposed `amendments:`-log audit (04-approach-a:84) measures the mechanism's *operation*, never the *underlying failure's existence*. It is the unmeasurable hinge under S1, and it sits beneath A's entire *identity* claim (as opposed to its methodology claim, which rests on the verified C3+C2). If this assumption is wrong, A pays cairn's largest append-only cost (5 ADRs + INV-003, R2) to canonize a value against a failure mode that may not be real for this repo — and that is exactly R2's surviving charge (`00-lead-findings.md:27-28`).
