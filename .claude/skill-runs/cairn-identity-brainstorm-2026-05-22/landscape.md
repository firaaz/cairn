## Scope & method

This document answers a single question for cairn's identity reframe: of the eight load-bearing claims behind cairn's medium-scale-cliff thesis (C1-C8), which remain load-bearing and which are now redundant given the native AI-dev runtime primitives that shipped or matured since cairn was conceived (~2024-2025)? Five surfaces were swept — Claude Code (official docs to ~v2.1.15x, May 2026, plus the GitHub issue tracker), OpenAI Codex (CLI + cloud + macOS app), Cursor/Windsurf IDEs, agent-orchestration SDKs and Aider, and 2024-2026 research/industry reports (arXiv primaries cross-checked against cairn's three named anchors). The method was adversarial: prosecute each claim for redundancy first (steelman the native runtime as a full replacement), then have a skeptic-verifier attempt to refute that prosecution against canonical repo files and the freshest external evidence, correcting the verdict where the prosecution overreached.

## Native-primitive inventory

### Claude Code (Anthropic CLI)

Headline finding: the native **subagent primitive now delivers BOTH halves of cairn's core need** — context isolation AND role reset — plus several adjacent primitives that qualify or break that guarantee.

- **Subagents (Agent tool, formerly Task; renamed v2.1.63).** Each runs in its own fresh, isolated context window — "does not see your conversation history, the skills you've already invoked, or the files Claude has already read." Only the final message returns to the parent ("intermediate tool calls and results stay inside the subagent"). The markdown body REPLACES the default system prompt (role-reset at the prompt layer). Per-subagent `model` (sonnet/opus/haiku/full-ID/inherit, 4-level resolution order), `tools`/`disallowedTools` allowlists, `permissionMode`, `maxTurns`, `effort`, `skills` preload, frontmatter hooks, persistent `memory`, and `isolation:worktree`. Subagents cannot nest. CAVEAT: CLAUDE.md + project memory + a parent git-status snapshot DO load into custom subagents (only built-in Explore/Plan skip them; no setting to change this) — so role-reset is clean at the system-prompt layer but NOT a clean-room w.r.t. project instructions. https://code.claude.com/docs/en/sub-agents
- **Forked subagents (`/fork`, `CLAUDE_CODE_FORK_SUBAGENT`, v2.1.117+).** A fork inherits the entire parent conversation, system prompt, tools, and model — deliberately DROPPING input-isolation. Output isolation preserved. When fork mode is on, general-purpose dispatches silently become forks; named subagents are untouched. The explicit ANTI-pattern to cairn's phase isolation. https://code.claude.com/docs/en/sub-agents
- **Agent teams (`CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS`, v2.1.32+, experimental).** Multiple full sessions coordinated by a lead via a Mailbox + shared task list; per-teammate plan-approval gating; TeammateIdle/TaskCreated/TaskCompleted hooks. Role-reset is weaker than subagents: a reused subagent definition body is APPENDED, not replacing, the system prompt, and skills/MCP frontmatter is dropped. https://code.claude.com/docs/en/agent-teams
- **Background agents / Agent View (`claude agents`, `/bg`; research preview May 11 2026).** Dashboard for many detached background SESSIONS; each burns quota independently. Distinct from in-session `background:true` subagents (which auto-deny any tool call that would prompt). https://code.claude.com/docs/en/agent-view
- **Skills (SKILL.md, `context:fork`, `agent:`).** Skills run INLINE by default (no isolation, no role-reset). `context:fork` runs the skill in an isolated subagent, returning only final text; `agent:` picks the executing agent type. A subagent's `skills:` frontmatter preloads skill content. This inline-vs-fork axis is exactly the axis cairn's design turns on. https://code.claude.com/docs/en/skills
- **Hooks (~30 events: PreToolUse/PostToolUse/SessionStart/SubagentStart/SubagentStop/PreCompact/InstructionsLoaded/...).** Deterministic shell commands; PreToolUse fires BEFORE permission-mode checks and can `deny` even under bypassPermissions — user-unbypassable policy. Exit-2-to-stderr blocks. Per-subagent frontmatter hooks (Stop→SubagentStop auto-conversion). This is cairn's entire enforcement substrate. https://code.claude.com/docs/en/hooks
- **Git worktrees (`--worktree`, `isolation:worktree`).** Native filesystem/branch isolation; subagent worktrees branch from the default branch by default (documented surprise, issue #50850). https://code.claude.com/docs/en/worktrees
- **Memory (CLAUDE.md hierarchy, auto-memory, `/remember`, per-subagent persistent memory, API memory tool).** CLAUDE.md re-injects fresh post-compaction; auto-memory saves cross-session notes; per-subagent `memory: user|project|local` gives a durable MEMORY.md store. https://code.claude.com/docs/en/memory
- **Plan mode + permission modes (default/acceptEdits/plan/auto/dontAsk/bypassPermissions).** Plan mode is read-only plan-before-execute, but is prompt-level (soft), not mechanically enforced — which is why cairn layers PreToolUse hooks on top. Parent bypassPermissions/acceptEdits/auto take precedence over a subagent's permissionMode. https://code.claude.com/docs/en/permission-modes
- **Plugins + MCP.** Plugin-provided subagents do NOT support hooks/mcpServers/permissionMode frontmatter — a concrete reason cairn could not be repackaged as a plugin without losing enforcement. Per-subagent inline mcpServers scope a surface to one phase. https://code.claude.com/docs/en/plugins-reference
- **Compaction (microcompaction, auto-compaction, PreCompact/PostCompact).** Subagent transcripts compact INDEPENDENTLY of the parent (agent-{id}.jsonl), reinforcing isolation. https://code.claude.com/docs/en/sub-agents

Four documented isolation failures: (1) background-subagent tool-log/secret leak to parent on result retrieval — issue #14118, closed-not-planned; (2) parallel-result aggregate overflow → terminal "Prompt is too long" crash — issue #23463, closed-not-planned; (3) Windows `isolation:worktree` Edit/Write leaking into the parent checkout — issue #57847, OPEN; (4) by-design fork de-isolation (docs). The first two mean the isolation guarantee is reliable only for FOREGROUND subagents with CAPPED returns.

### OpenAI Codex (CLI + cloud + macOS app)

Independent convergence on most of cairn's primitives, with a different enforcement philosophy.

- **Custom agents / subagents (`.codex/agents` TOML; GA 2026-03-16).** `developer_instructions` per-agent system prompt; optional per-agent `model`, `model_reasoning_effort`, `sandbox_mode`, `mcp_servers`, `skills` — cairn's role-brief + per-role permissions + per-role model decomposition. KEY DIFFERENCE: opt-in capability roles invoked ad hoc, NOT an enforced fail-closed ordered sequence. https://developers.openai.com/codex/subagents ; https://simonwillison.net/2026/Mar/16/codex-subagents/
- **Built-in agents: default / worker / explorer.** OpenAI shipped essentially cairn's role taxonomy (explorer=read-only research, worker=mutating execution, default=general) — strong external corroboration of the read-vs-write cleavage. https://developers.openai.com/codex/subagents.md
- **Subagent orchestration & thread isolation.** Model-driven dynamic spawn/route/join with consolidated fan-out results. Per-subagent CONTEXT-WINDOW isolation is only implied (thread-level), never explicitly documented as a fresh-context guarantee.
- **Sandbox modes (read-only / workspace-write / danger-full-access).** OS-enforced (macOS Seatbelt, Linux/WSL2 bubblewrap, native Windows sandbox) — the kernel-backed analog to cairn's hook-based write gating. Subagents INHERIT the parent's sandbox and can only re-tighten. https://developers.openai.com/codex/concepts/sandboxing
- **Approval policies (untrusted/on-request/never/granular) + auto_review reviewer agent.** Cleanly separates CAN (sandbox) from MAY (approval), an axis cairn conflates. `auto_review` runs an LLM gatekeeper on a separate thread before execution — aimed at exfil/creds/destructive ops rather than scope-drift. https://developers.openai.com/codex/agent-approvals-security
- **Cloud task isolation (per-task containers) + secrets lifecycle.** One container per task, network-off by default during the agent phase; secrets decrypted for setup only and STRIPPED before the autonomous agent phase — a phase-scoped privilege-reduction pattern. https://developers.openai.com/codex/cloud/environments
- **AGENTS.md custom instructions.** Cross-vendor open standard (Aug 2025; donated to the Linux Foundation's AAIF Dec 2025), root-down concatenation, nearest-file-wins, 32 KiB cap — shared session memory, the opposite of per-phase isolation. https://developers.openai.com/codex/guides/agents-md ; https://www.infoq.com/news/2025/12/agentic-ai-foundation/

### Research & reports (2024-2026)

- **Cross-Context Review (CCR), Song, 2026-03-12 — cairn's own anchor, re-confirmed.** Fresh-session review beats every same-session variant; F1 28.6% vs 24.6% self-review (+4pp, p=0.008); the gain is context SEPARATION, not looking twice. arXiv:2603.12123
- **"More Rounds, More Noise," Song, 2026-03-18 (NEWER).** Iterative same-session review HURTS verification; one fresh pass wins. arXiv:2603.16244
- **DACS, Patel, 2026-04 (NEWER).** Quantifies the cliff: flat-context orchestrator steering collapses 60.0% (N=3) → 38.7% (N=5) → 21.0% (N=10); wrong-agent contamination 28-57%; isolation restores 90-98% / 0-14%. arXiv:2604.07911
- **EPSS / CodeDelegator, Fei et al., 2026-01-22 (NEWER).** Independent re-derivation of fresh-stateless-coder-per-subtask; prior execution state treated as pollution. arXiv:2601.14914
- **Specification Gap (2026) + MAST (NeurIPS 2025, 1,600+ traces).** Integration failure is STRUCTURAL: single-vs-multi gap stays 25-39pp at every spec level; 79% of prod breakdowns are spec/coordination/verification gaps. arXiv:2603.24284 / arXiv:2503.13657
- **"From Biased Chatbots to Biased Agents," Cao et al., 2026-02.** Task-irrelevant personas cause up to 26.2% degradation, concentrated in reasoning/planning, across three model families. arXiv:2602.12285
- **Nautilus Compass, Wang, 2026-05-12.** Persona drift is UNSOLVED and long-form memory systems (Mem0/Letta/Zep) ACCELERATE it; field ships detectors, not cures — directly rebuts "memory fixes drift." arXiv:2605.09863
- **Context rot (Chroma 18 models; Adobe, Feb 2025; LOCA-bench).** Architectural, not transient: simple-retrieval at 32K drops Claude 3.5 Sonnet 88%→30%, GPT-4o 99%→70%; bigger windows shift the threshold, not the failure. arXiv:2602.07962
- **Correlated Errors, Kim et al., ICML 2025 — cairn's own anchor.** ~60% cross-family error agreement; same-family preference leakage. Fresh-CONTEXT review removes within-session contamination but NOT shared-weights blind spots. arXiv:2506.07962
- **COMPLICATION (the one weakening signal): Anthropic context-editing + memory tools** yield +29%/+39% lifts and 84% token reduction — but every source frames these as COMPLEMENTS that fix token-exhaustion/recall, explicitly NOT role contamination, drift, integration, or context-clash, for which they still prescribe subagent isolation. anthropic.com/news/context-management

The verifier corrected the prosecution's "partially-redundant" to "still-load-bearing" on a category error: C1 is a claim that a failure MODE exists, not that a solution is unique — a mechanism shipping natively does not dissolve the failure mode it targets. Cairn's own live reframe (`docs/plans/2026-05-22-cairn-identity-direction.md`) verbatim PRESERVES the cliff scope while retiring the machinery the prosecution attacked. Honest caveat: the cliff ADR is `firmness:provisional` and its 50-files/5k-LOC/6-months threshold is self-admittedly "intuition, not empirical" and unobserved in cairn itself — well-supported theoretically and by fresh external evidence, but cairn-internally unvalidated.

**C2.** The verifier downgraded the prosecution's "now-redundant" to "partially-redundant," verified against the CANONICAL spec-v1 (lines 35-45), where the claim is a DUAL mechanism with two distinct named halves: context-engineering ("loads ONLY the committed artifact") and a HUMAN role-RESET (author→critic switch), with role-PURITY called out separately as the "most defensible." That premise is structurally falsified: each subagent runs in a fresh window and ONLY the final message returns — the reasoning trace C3 fears cannot re-enter the parent. Operationally, cairn already neutralized the residual: `SKILL.md` steps 5/7/9/11 parse only `status`+`commit_hash` and rebuild each next brief from git-committed artifacts (verifying via `git show`/pytest/validator) — so the inter-phase channel is the committed FILE, not the return string; phase agents cap returns at `summary:"<=100w"`. ## The residual cliff

Native runtimes have erased exactly ONE leg of cairn's four-legged premise — context-window exhaustion / "just pour everything into one long session" — via compaction, microcompaction, CLAUDE.md re-injection, and Anthropic's context-editing + memory tools (+29%/+39%, 84% token reduction). Cairn pre-concedes this in spec-v1 §1/why-cairn line 9. The other three legs survive native mitigation and, per the newest evidence, are WORSENING:

1. **Role contamination / correlated blind spots.** Native subagents reset context WITHIN a dispatch, but ~60% cross-family error agreement plus same-family preference leakage (Kim et al., ICML 2025) means a same-model fresh-context reviewer still shares weights-level blind spots. Role/persona contamination causes up to 26.2% degradation concentrated in reasoning/planning across three model families (arXiv:2602.12285). The strongest form of the bet needs cross-MODEL review, which neither cairn nor native primitives yet enforce.

2. **Cross-session / multi-month drift.** ADR↔code semantic drift over ~50 files / 6 months lives ABOVE any single subagent dispatch and is untouched by per-dispatch isolation. Persona drift is UNSOLVED and ACCELERATED by the very memory tools cited as the cure (Nautilus Compass, May 2026) — the field ships detectors, not prevention.

3. **Structural integration failure.** The single-vs-multi-agent gap never narrows to zero at any specification level (25-39pp persistent); MAST attributes 79% of production breakdowns to spec/coordination/verification gaps. This is intrinsic to multi-agent handoff, not a prompt-quality artifact.

The deepest residual: native subagents provide the per-phase MECHANISM (isolation + role-reset + per-phase model) for free, but the cliff actually forms across the SLICE CORPUS — and the cross-slice coherence CONTRACT has no native equivalent. That contract is: deterministic phase ordering, fail-closed independently-anchored write envelopes (role_guard), an append-only ADR substrate with machine-checkable invariant binding, and PreToolUse hard-enforcement that fires even under bypassPermissions. DACS (arXiv:2604.07911) is direct quantitative measurement that this is a discontinuous cliff, not a gentle erosion: flat-context steering collapses 60%→21% from N=3 to N=10 agents.

## Implications for the follow-up arcs

These are FINDINGS, not recommendations.

**For brainstorm #1 (methodology replacement — can subagent orchestration preserve isolation + role-reset?).** The evidence says native subagents preserve isolation + role-reset **at the level of a single dispatch**, conditionally — only for FOREGROUND, NAMED, capped-return subagents — and only as role-PURITY (system-prompt swap), not the human author→critic role-RESET, and NOT as a clean-room (CLAUDE.md/memory/git-status bleed in). C3-as-written ("subagents defeat isolation") is now-redundant, removing the original objection to subagent-based phases. But the dual mechanism is NOT automatically preserved across a multi-PHASE pipeline orchestrated from one parent: cairn's own spec (spec-v1 §3/§14 incident #3) and the documented return-channel failures (#23463 aggregate overflow; #14118 background leak) show isolation degrades on the RETURN channel when the orchestrator accumulates each phase's return. Cairn's shipped skill already sidesteps this by passing committed-file pointers (not return strings) as the inter-phase channel and capping returns at ≤100-200 words. The finding: subagent orchestration CAN preserve isolation + role-reset IF the orchestration (a) keeps the inter-phase channel a committed artifact not the prose return, (b) hard-caps return size, (c) runs foreground with named agents, (d) treats `CLAUDE_CODE_FORK_SUBAGENT` as hostile — and it still does NOT preserve the human role-reset half (unfalsifiable per spec-v1 §17) nor the fail-closed write-gate, which remain cairn-supplied.

**For brainstorm #2 (intent-file shape — runtime-specific constraints found).** AGENTS.md is now a cross-vendor open standard (Codex, Cursor, Windsurf; Linux Foundation AAIF) with a 32 KiB / `project_doc_max_bytes` default cap and root-down-concatenation/nearest-wins semantics — a portable, tool-agnostic instruction surface, but a SHARED merged-context mechanism, the opposite of per-phase isolation. Claude Code's CLAUDE.md survives compaction (re-injected fresh from disk) and loads into all custom subagents (only Explore/Plan skip it, with no setting to change which), which is both why safety-critical rules belong there and why it is the operator-memory leakage vector cairn already warns about. Windsurf's four rule-activation modes (always-on / model-decision / glob / manual) formalize the lazy-load context-budget dial cairn currently does by hand. The cap and the load-on-demand modes are concrete runtime constraints an intent-file shape would encounter; the AGENTS.md-vs-CLAUDE.md split is a portability-vs-compaction-survival trade-off.

**For the ADR-sufficiency arc (what native memory/knowledge features already cover).** Native memory covers storage, recall, and token-economy: per-subagent persistent memory (MEMORY.md, first 200 lines/25KB), CLAUDE.md surviving compaction, auto-memory cross-session extraction, MCP knowledge servers for retrieval/indexing of an ADR corpus, IDE semantic indexing, and the context-editing memory tool. What native features do NOT cover, per C6's evidence: fail-closed coverage ENFORCEMENT (the validator currently exits 1 on a real coherence violation), append-only supersession discipline, machine-checkable prose-to-code assertion binding, and deterministic operation. Nautilus Compass's finding that long-form memory systems ACCELERATE drift is a direct caution against treating native memory as a coherence substrate. The semantic-drift sub-case (prose meaning shifts while the structural cross-reference still passes) is unsolved in cairn too — neither native memory nor cairn's validator catches it.

## Open questions & evidence gaps

- **C5, C6, C7, C8 were not skeptic-verified** (`verified: null`, `verifier_note: null`). Only C1-C4 went through the prosecute-then-verify loop. The four unverified verdicts rest on the analyst's self-rated confidence and one-line deciding-evidence fields, not an independent refutation attempt — they are the lowest-rigor verdicts in this arc despite carrying "high" self-confidence. C5's deciding-evidence and load-bearing-case are notably terse.
- **The cliff (C1) is cairn-internally unvalidated.** The 50-files / 5k-LOC / 6-months threshold is `firmness:provisional` and self-admittedly "intuition, not empirical," never observed in cairn itself. External literature corroborates the failure modes, but cairn has no first-party measurement of its own cliff.
- **Codex per-subagent context-window isolation is doc-unconfirmed.** Official docs and Simon Willison's writeup confirm distinct THREADS and consolidated results but never explicitly state a fresh-context guarantee or that parent conversational memory is withheld — "thread isolation = full context isolation" is likely-but-not-doc-confirmed for Codex.
- **LangGraph isolation quotes are secondary-sourced.** Official LangGraph doc URLs returned JS-redirect/404 shells via WebFetch; the exact-quote wording ("the subgraph's state keys never appear in the parent's state") is verified from a corroborating blog and search excerpts, not a clean primary fetch — high-confidence-but-secondary.
- **Date provenance was unreliable for two surfaces.** The Codex changelog WebFetch garbled dates (returned "May 2021," clustered everything into "May 2026") and was NOT trusted — dates were recovered from named primary sources instead. Cursor's live changelog index carried only recent entries; Cursor Memories' June-2025 month is medium-confidence (secondary sources), and Windsurf's dedicated Plan Mode maturation wave is not pinned to a single primary entry.
- **The human role-reset half (C2) is unfalsifiable.** Per spec-v1 §17, neither sessions nor subagents can prove or disprove the author→critic psychological switch; this arc cannot determine whether native primitives render it redundant because it cannot be tested at all.
- **Cross-MODEL review is an under-exploited extension, not a finding about native coverage.** Subagents ENABLE per-subagent model selection, but neither cairn nor any native runtime ENFORCES cross-model review; whether cross-family verification meaningfully reduces the ~60% correlated-error floor in cairn's actual decisions was not measured here.
- **The continuous-replanning alternative (Windsurf) was not adjudicated.** Whether a background planning-agent that continuously re-refines the plan while an executor acts beats hard phase boundaries — or reintroduces the phase-blur cairn forbids — was flagged but not resolved by this arc.
