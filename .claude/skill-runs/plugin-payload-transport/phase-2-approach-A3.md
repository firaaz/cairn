# Phase 2 — Approach A3 (Self-marketplace)

## 1. Sub-variant pick — **A3a** (dev branch carries marketplace.json + bundled payload under `./dist/`)

**Pick A3a.** Rationale:

- Marketplace-add against `https://github.com/firaaz/cairn` HTTPS-clones the **default branch (`dev`)**, where `.claude-plugin/marketplace.json` already lives today. No `-b release` qualifier, no default-branch swap, no consumer-doc churn. This honors the D2/D3 "consumer commands remain UNCHANGED" lock (constraints:39).
- The `dist/` directory already exists on `dev` (built by `scripts/build_dist.py` for dogfood/dist-gate CI). Pointing `source` at `"./dist"` reuses the existing curation pipeline (D3, `m5-plugin-distribution-and-symlink-retire.md:55-68`) — no rebuild of the allow-list contract.
- INV-011 (`.slice-system → .` self-symlink at repo root) survives: marketplace-add clones to `~/.claude/plugins/marketplaces/cairn-marketplace/` — the symlink resolves locally inside that clone, but plugin-install only copies from `./dist/` which `build_dist.py:54-55` explicitly ignores (`shutil.ignore_patterns(".slice-system", …)`).

**A3b rejected because:** requires either (a) `release` as default branch (silently breaks every existing clone, PR review against `dev`, and the dist-gate workflow which compares PR's built dist against `dev`-tip), or (b) consumer typing `-b release` (violates "consumer commands UNCHANGED", constraints:39). It also collapses the dev/release split — dist-gate.yml's PR-time gating, which compares `dev`-built dist against a candidate, loses its reference branch. The dev/release separation is load-bearing for INV-012's "release is CI-deterministic deploy target."

## 2. Shape

**On `dev` post-A3a** (additive, not restructure):
- `dist/` continues to exist, regenerated by `build_dist.py` (no schema change).
- `.claude-plugin/marketplace.json` rewritten to a relative-path source.
- `release` branch is **retained** as the curated archaeology anchor + tag target (D8), but the consumer install path no longer touches it.

**marketplace.json diff**:

```json
{
  "name": "cairn-marketplace",
  "owner": { "name": "firaaz" },
  "plugins": [
    {
      "name": "cairn",
      "description": "TDD-by-construction dispatch skill, hooks, and protocols for Claude Code.",
      "source": "./dist"
    }
  ]
}
```

Object-form `source` collapses to the string-relative-path shape used by Anthropic's `agent-sdk-dev` plugin.

**release-publish.yml sketch.** Two changes:
1. **New step** (runs *before* the release-branch sync, on `dev` checkout): commit the freshly-built `dist/` back to `dev` via a release-bot push so consumers cloning `dev` get the latest payload. Guarded `if: github.event_name == 'workflow_dispatch'`. Uses `chore: release v${VERSION} dist refresh` (INV-001 compliant) + `--force-with-lease` to `dev`. **Alternatively (preferred — no `dev` force-push):** require `dist/` to be committed-current at workflow start, and fail fast if `git diff --quiet dist/` after rebuild is non-empty. Operator commits `dist/` on the release PR; workflow only verifies + tags.
2. **Retained:** release-branch sync + tag (`v${VERSION}`). The `release` branch becomes the archaeology anchor; it is no longer the consumer install target.

**build_dist.py sketch.** Default `dist_root` stays `repo_root / "dist"` — no change. Only addition: a one-line invariant assertion that `dist/.claude-plugin/plugin.json` exists post-build (already implicit).

## 3. How A3a bypasses SSH

Stage 3 (phase-0.5-journey:28-48) **does not occur**. There is no second clone.

Pipeline:
1. `/plugin marketplace add https://github.com/firaaz/cairn` → resolver HTTPS-clones the repo to `~/.claude/plugins/marketplaces/cairn-marketplace/` (Stage 2; phase-0.5-journey:19 confirms HTTPS works here).
2. `/plugin install cairn@cairn-marketplace` → resolver reads `marketplace.json`, sees `"source": "./dist"`, resolves it **relative to the marketplace clone dir** — payload is already on local disk. Plugin-install is a filesystem copy from `~/.claude/plugins/marketplaces/cairn-marketplace/dist/` into the install tree.
3. **No `github.com` host routing fires** — there is no URL for the resolver to clone. The host-based SSH-forcing failure mode (framing.md:9-13, sweep-notes V-3 attempts 1+2) is structurally unreachable.

Citation: `research-anthropic-marketplace.md:46-48,69-77` — 49/82 of Anthropic's plugins use string-relative-path sources; marketplace-add HTTPS-clones the marketplace repo; plugin-install is a filesystem copy from the cached marketplace dir; no second clone needed; no SSH path at all.

## 6. Risks specific to A3a

- **R-A3a-1 — Source-tree leakage.** Marketplace-add clones the entire cairn repo (scripts/, docs/, tests/, ADRs, plans) into `~/.claude/plugins/marketplaces/cairn-marketplace/`. Plugin-install only copies `./dist/`, so the *installed* plugin tree stays curated — but the cached marketplace dir contains the full source. Consumers grepping their `~/.claude/plugins/` see cairn-internal docs/ADRs/tests they shouldn't reason from. Mitigation: README note + accept it; this matches how Anthropic's 49 self-marketplace plugins behave.

- **R-A3a-2 — dist-gate semantics shift.** Today dist-gate.yml gates PRs against `dev` by rebuilding `dist/` and comparing. Under A3a, **`dist/` must be committed-current on `dev` at all times** because it's the consumer install target. Stale-`dist` PRs become a release-blocking failure mode, not just a CI hint. The gate must escalate from advisory to mandatory + auto-rebuild-and-commit on merge.

- **R-A3a-3 — `dev`-branch instability bleeds to consumers.** `dev` carries WIP commits, half-landed slices, broken intermediate states. The moment `dist/` is committed-current on `dev`, every `dev` push that touches `dist/` becomes consumer-visible. Mitigation: keep `dist/` commits gated to release-publish moments (operator-only `chore: release` commits); WIP slice work never touches `dist/`.

- **R-A3a-4 — INV-011 .slice-system risk in bundled payload.** `.slice-system → .` is at repo root; marketplace-add clones it. macOS/Linux git preserves symlinks; the consumer's marketplace cache dir contains a working self-recursive symlink. Any consumer-side tool that walks `~/.claude/plugins/marketplaces/cairn-marketplace/**` with `followlinks=True` will infinite-loop. `build_dist.py` already excludes it from `dist/`, so the *installed* plugin is safe — but the marketplace cache dir is a footgun. Mitigation: verify Claude Code's marketplace-cache walkers do not follow symlinks; document the hazard in operational-reference.md.

- **R-A3a-5 — Test-marketplace-schema assertion erosion.** Three of the five currently-green schema-lint assertions go away. INV-012's defensive net thins. Mitigation: replace with positive assertions on `./dist` shape + on `dist/.claude-plugin/plugin.json` existence + version-string shape.

## 7. Adversarial steelman against A3

**"This is a deep restructure for an unverified Anthropic-resolver hypothesis."**

The string-relative-path resolution behavior is asserted from population pattern (49 of Anthropic's plugins use it; research-anthropic-marketplace.md:46-48) and from Anthropic's own `agent-sdk-dev` plugin shape, but **we have not empirically verified** that Claude Code's resolver, when handed a relative-path source, treats it as marketplace-cache-relative rather than re-resolving via host-based routing. The same resolver that ignored cairn's declared `source: "url"` and force-routed to SSH for github.com (sweep-notes V-3 attempts 1+2) might also surprise us here.

**Counter:** A3a's hypothesis is weaker than A1's. A1 hinges on "the resolver routes `url`-type differently based on `sha:` vs `ref:` pinning." A3a hinges on "when `source` is a relative path string, the resolver resolves it against the marketplace clone dir" — a behavior we can read from the structure (there is no URL/host to route on; the *only* sensible interpretation is filesystem-relative) AND from 49 working examples in production. A3a is the lower-risk hypothesis. **But the steelman bites on cost asymmetry:** A1's probe is a 5-line marketplace.json edit; A3a's probe requires `dist/` to be committed and a probe branch with a viable default-branch override path. If A3a falsifies, we've wasted more setup than A1 would have. **Recommendation downstream:** run A1 probe first (cheap), and only escalate to A3a if A1 falsifies. A3a stays the strong second-rank because it has the cleanest "no-SSH-by-construction" story.

**Second adversarial line — A3a permanently fuses marketplace and source repo.** Today cairn-the-repo and cairn-the-plugin are distinguishable: `dev` is source, `release` is shipped payload. A3a collapses that: `dev` is both. The dev-branch-instability risk (R-A3a-3) is the lived form of this collapse — once consumers install from `dev`, every `dev` push is a potential consumer-visible event, even if cached.

**Counter:** The separation is already partial. Today `dist/` lives on `dev` for dogfood. The `release` branch is purely a CI artifact; it carries no information not derivable from `dev` + `build_dist.py`. A3a makes the existing partial collapse explicit. The collapse is honest, not lossy.
