### What and Why

Complete ADR `identifier-scheme` §D7 Phase 2 Part 2: make every active slice and feature entity conform to the canonical identity shapes declared by §D2 and §D5, and retire `.claude/sweep.yaml`'s `current-slice-number` field per the §D7 Phase 2 cleanup list. Why it matters: until this slice lands, four of five feature files still carry legacy `SLICE-NNN` slice entries or a `slice-yaml-id:` transitional bridge, and `current-slice-number` remains a monotonic counter that duplicates information now expressed by semantic IDs and git history — the very ambiguity source ADR `identifier-scheme` D7 flags for retirement. After this slice, INV-005 compliance is load-bearing on actual files (not on transitional prose), `scripts/dogfood_evaluate.py` no longer reads a field that no longer exists, and `identifier-scheme/doc-sweep` can focus on residual prose with a clean substrate beneath it.

### Specification Detail

**1. Feature file schema — canonical shape.** Every file at `.claude/features/<id>.yaml` carries these top-level fields:

| Field | Required? | Notes |
|---|---|---|
| `id:` | yes | Flat semantic slug matching the filename stem. Unchanged for existing files. |
| `name:` | yes | Short human-facing label per ADR `identifier-scheme` D6 conventions. Added if absent. |
| `intent:` | yes | Prose statement; preserved verbatim if already present. |
| `shaped-from:` | yes | Path, URL, or `null` per ADR `identifier-scheme` D5. Added if absent. |
| `created:` | yes | `YYYY-MM-DD`; preserved. |
| `slices:` | optional | List of slice entries, shape below. |

**2. Slice-list entry — canonical shape.** Every entry under a feature's `slices:` list carries:

| Field | Required? | Notes |
|---|---|---|
| `id:` | yes | Hierarchical `<feature-id>/<slice-slug>` per ADR `identifier-scheme` D2. No `SLICE-NNN` form. |
| `added:` | yes | `YYYY-MM-DD`; preserved. |
| `after:` | optional | List of hierarchical slice-ids. Legacy `SLICE-NNN` values MUST be migrated to their corresponding hierarchical id. |
| `intent:`, `note:`, `status:`, `reason:` | optional | Preserved as-is; semantics unchanged from feature-slice-model. |
| `slice-yaml-id:` | **removed** | Bridge retired. Successful slices' `slice.yaml` is wiped on close (context-discipline-protocol INV-002 via start-slice Step 7); the bridge pointed at archaeological identifiers best recovered by `git log --follow`. |

**6. `slice-yaml-id:` bridge removal.** Delete every `slice-yaml-id:` line from `.claude/features/identifier-scheme.yaml` (6 entries) and `.claude/features/housekeeping.yaml` (2 entries). Do not replace with any other field — the hierarchical `id:` is self-sufficient. Keep the bootstrap-window CONSTRAINT comment block atop `identifier-scheme.yaml` intact; it is human-readable context, not a bridge.

**7. `.claude/sweep.yaml` shape change.** The file transitions from:

```yaml
last-sweep-at-slice: 22
sweep-interval: 1
current-slice-number: 23
```

to:

```yaml
last-sweep-at-slice-id: identifier-scheme/adr-rename-sweep
sweep-interval: 1
```

`last-sweep-at-slice-id:` names the slice whose completion triggered the most recent sweep (sweep #16 was triggered post-`identifier-scheme/adr-rename-sweep`). The `current-slice-number` field is removed; `last-sweep-at-slice` (unsuffixed numeric form) is replaced by `last-sweep-at-slice-id`.

**8. Sweep-due computation.** After retirement, `/start-slice complete` determines whether an integration sweep is due by:

```
completed_since_last_sweep = count of commits on the current branch matching
    `^slice: .* — complete$` since commit-of(last-sweep-at-slice-id),
    exclusive of that commit itself
sweep_due = completed_since_last_sweep >= sweep-interval
```

Commit-of(slice-id) is the first commit matching `^slice: <slice-id> — complete$`. If `last-sweep-at-slice-id:` is `null` or the slice cannot be located in history, the implementation MUST fall back to "sweep due" and print a one-line diagnostic on stderr — conservative default so sweeps are not silently skipped during a missing-pointer edge case. `/integration-sweep` writes the completing slice's id into `last-sweep-at-slice-id:` at the end of every successful sweep.

**9. `scripts/dogfood_evaluate.py` re-plumbing.** Its existing `_read_sweep_yaml` helper is replaced by a git-log counter: post-cliff slice count is the number of `^slice: .* — complete$` commits since the commit that introduced `docs/adr/cliff-failure-mode-and-v1-defenses.md`. The CLI surface (flags, exit codes 0/1/2, stdout/stderr format) is preserved. The dogfood-log.md frontmatter field `adr-003-landed-at-slice` becomes meaningless once `current-slice-number` is retired — Phase 2/3 MUST either (a) change its semantic to a commit sha or slice-id, or (b) drop it and read the baseline commit directly from `docs/adr/cliff-failure-mode-and-v1-defenses.md`'s first-commit sha. The dogfood-log.md file itself is out of envelope because it is a historical operator log, not a protocol substrate.
